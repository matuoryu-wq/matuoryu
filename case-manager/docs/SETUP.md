# セットアップ手順書(Windows PC)

案件データは **この Windows PC の中だけ** に保存されます。iPhone・他の Windows からは
Tailscale(私設ネットワーク)経由の HTTPS でアクセスします。インターネットには公開しません。

## 1. 必要なもの

| もの | 入手先・備考 |
|---|---|
| Python 3.11 以上 | https://www.python.org/ ― インストール時「Add python.exe to PATH」にチェック |
| Tailscale | https://tailscale.com/download ― PC と iPhone の両方に入れ、同じアカウントでログイン |
| バックアップ用の別ドライブ | 外付けHDD・別パーティション等(例: `D:\case-backup`) |

## 2. 初回設定

1. このフォルダ(`case-manager`)を PC の任意の場所に置く(例: `C:\case-manager`)。
2. `.env.example` をコピーして `.env` を作る。
3. アクセストークンを生成し、`.env` の `APP_TOKEN=` に貼る。
   ```
   py -3 -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
   - トークンはパスワードと同じ扱い。パスワード管理ソフトに保管し、メール等で送らない。
4. `.env` の `BACKUP_DIR=` に別ドライブのフォルダを指定(例: `D:\case-backup`)。
5. 案件フォルダの置き場所を `ALLOWED_FOLDER_ROOTS=` に指定(例: `C:\Users\me\Documents\事件`)。
   これ以外の場所はアプリから参照できなくなる。
6. `start.bat` をダブルクリック。初回は必要なライブラリを自動でインストールする。
   「Uvicorn running on http://127.0.0.1:8765」と出れば起動完了。
7. PC のブラウザで http://127.0.0.1:8765 を開き、トークンでログイン。

> サーバーは `127.0.0.1`(この PC 自身)でしか待ち受けません。LAN の他の機器から直接は接続できません。

## 3. iPhone・他の PC からの接続(Tailscale Serve)

管理者権限のコマンドプロンプト(または PowerShell)で:

```
tailscale serve --bg 8765
tailscale serve status
```

`https://<PC名>.<tailnet名>.ts.net/` のような URL が表示されます。
この URL は **同じ Tailscale ネットワークに参加した端末からのみ** 開けます。

- `tailscale funnel` は **使わない**(インターネット公開になります)。
- Tailscale 管理画面で「HTTPS Certificates」を有効にしておく(初回のみ。Serve 実行時に案内が出ます)。
- 停止するとき: `tailscale serve reset`

### iPhone

1. Tailscale アプリを入れて同じアカウントでログインし、VPN をオンにする。
2. Safari で上記 URL を開き、トークンでログイン(iCloud キーチェーンに保存可)。
3. 共有ボタン →「ホーム画面に追加」。以後はアプリのように起動できます。

## 4. PC 起動時に自動起動する(任意)

1. `Win + R` → `shell:startup` でスタートアップフォルダを開く。
2. `start.bat` のショートカットを置く。

## 5. バックアップ

- サーバー稼働中は 1 時間ごとに確認し、前回から 24 時間経過していれば自動でバックアップします。
- PC を常時起動しない場合は、タスクスケジューラでも日次実行してください:
  ```
  schtasks /Create /SC DAILY /ST 12:30 /TN "案件管理バックアップ" /TR "C:\case-manager\backup.bat"
  ```
- 世代数は `.env` の `BACKUP_KEEP`(既定 30)。古いものから自動削除。
- 最終バックアップ日時はダッシュボード下部・「その他 → 設定」に表示。48 時間以上空くと警告。
- 復元: サーバーを停止し、`data\cases.sqlite3` をバックアップファイルで置き換える
  (`cases.sqlite3-wal`・`-shm` があれば削除してから)。

## 6. セキュリティ上の注意

- `.env` は他人に渡さない・クラウド同期フォルダに置かない。Git にも含まれません(`.gitignore` 済み)。
- トークンを変更したら `.env` を書き換えてサーバーを再起動。全端末で再ログインが必要になります。
- 機微案件(案件編集で「機微案件」にチェック)は、閲覧・変更時にトークンの再入力を求めます
  (有効時間は `REAUTH_MINUTES`、既定 10 分)。一覧・検索・通知では題名が伏せられます。
- ログイン失敗が 10 分間に 5 回続くと一時的にログインを拒否します。
- 操作ログ・監査ログ(「その他 → 操作ログ」)に、ログイン、すべての変更操作、機微案件の閲覧、
  資料の閲覧、利益相反チェック、期限の確定が記録されます。
- PC 自体の BitLocker(ドライブ暗号化)と画面ロックを有効にしてください。

## 7. v2: AI・文字起こし・資料の索引化

### 7-1. AI(Claude API)

1. https://console.anthropic.com/ で API キーを発行し、`.env` の `ANTHROPIC_API_KEY=` に設定。
2. サーバーを再起動。案件の「AI」タブが使えるようになります。

**送信の流れと安全策**

- AI に送るのは、ボタンを押したときの 1 回分だけです。自動送信はしません。
- 送信前に、当事者の氏名・読み・姓/名・住所・電話・メール・会社名・事件番号を【依頼者1】などの記号に置き換えます。
  異体字(髙/高、齋/斎/斉 等)・カタカナ/ひらがな・全角/半角・「㈱」等の揺れも置換します。
- 辞書にない会社名・住所・電話番号・メール・郵便番号・口座番号、「〇〇さん/様/氏/部長」の〇〇、
  登録名と1字違いの「」書きの名前(言い間違い)も自動で置換します。
- 送信直前に置換漏れ検査を行い、1語でも残っていれば **送信しません**。
  その場合は「AI」タブの「追加の匿名化語」に登録してください。
- 「確認して送信」で、実際に送る本文と置換一覧を確認してから送信できます。
- 送信内容(匿名化後)・応答・モデル・トークン数は「その他 → AI送信ログ」に残ります。置換表はこの PC 内だけに保存されます。
- **限界**: 敬称のない第三者の氏名(例: 文中に突然出てくる「鈴木花子」)は自動では検出できません。
  当事者・関係者として登録するか、追加の匿名化語に登録してください。送信前の確認画面で本文を確認する運用を推奨します。

**出力について**

- 出力はすべて「初稿」です。各記述に出典(ファイル名とページ、録音の時刻、活動記録)が付き、タップで原典を開けます。
- 出典の引用が実際に資料に存在するかを自動照合し、「一致 / 部分一致 / 不一致 / 出典なし」を表示します。
  不一致・出典なしの記述は赤枠で表示されます。
- 相談メモの見出しは「設定」で事務所様式に合わせて変更できます。

### 7-2. 資料フォルダの索引化

案件の「資料」タブで「本文を索引化」を押すと、紐付けたフォルダの PDF・Word・Excel・メール(.eml/.msg)・テキストの
本文を抽出し、その案件の中だけで検索できるようにします。2回目以降は変更のあったファイルだけを処理します。

**スキャン PDF の OCR(任意)**: Tesseract をインストールすると、文字のないページを OCR します。
1. https://github.com/UB-Mannheim/tesseract/wiki からインストーラーを入手し、「Additional language data」で Japanese を選んでインストール。
2. インストール先(例: `C:\Program Files\Tesseract-OCR`)を環境変数 PATH に追加し、サーバーを再起動。
3. 「設定」の AI・文字起こしの状態で OCR が「利用可」になっていることを確認。

### 7-3. 録音の文字起こし(PC内で処理)

- `start.bat` の初回セットアップで faster-whisper をインストールします。
- 初回の文字起こし時に Whisper モデルをダウンロードします(数百MB。**音声は送信されません**)。
  `.env` の `WHISPER_MODEL` で精度と速度を選べます(CPU では `small`〜`medium` が目安。1時間の録音で数十分程度)。
- 話者分離を使う場合は `pip install pyannote.audio` のうえ `DIARIZATION=pyannote` と `HF_TOKEN` を設定
  (Hugging Face でモデルの利用条件への同意が必要)。未設定の場合は、画面で話者名を付けてください。

**iPhone のボイスメモから取り込む**
1. ボイスメモで録音を選び、共有 →「"ファイル"に保存」。
2. 案件の「録音」タブで「録音ファイル」を選び(ファイル App から選択)、「取り込んで文字起こし」。
3. 完了すると、時刻つきの文字起こしが活動記録(面談)に保存され、AI の資料にも使われます。
   話者名の付け替え・誤認識の修正は「録音」タブで行えます(活動記録にも反映)。

### 7-4. 稼働・報酬・採算

- 稼働時間は活動記録の「所要時間(分)」を集計します(録音は長さから自動入力)。
- 案件の「会計」タブで、請求・入金(着手金・報酬金・日当等)、実費の立替、**預り金(報酬と分けて管理)** を記録します。
- 「その他 → 稼働・採算」で案件別の時給換算(入金ベース)を確認できます。

### 7-5. AI 出力の評価(プロンプトを変えたとき)

`app/prompts/` のプロンプトやモデルを変更したら、評価セット(`tests/fixtures/eval/`)で悪化がないか確認します。

```
.venv\Scripts\python.exe scripts\eval_ai.py --live --record eval-runs\初回 --save-baseline   (最初の基準を作る)
.venv\Scripts\python.exe scripts\eval_ai.py --live --record eval-runs\変更後                 (変更後に比較)
```

日付・当事者名・争点・未確認事項の有無、出典の実在、匿名化漏れを機械的に採点し、基準より悪化した項目を表示します
(1回の実行で 4 件の API 呼び出し)。`--replay eval-runs\変更後` で保存済みの応答を再採点できます(API 不要)。

## 8. 動作確認用データ

練習用に模擬事件を投入できます(**実事件のデータベースには投入しないこと**)。
別の `DATA_DIR` を指定した試用環境で:

```
.venv\Scripts\python.exe scripts\load_demo.py
```

模擬事件フォルダ(PDF・Word・メール等)は `tests/fixtures/make_folder.py` で作れます。

## 9. テストの実行

```
.venv\Scripts\python.exe -m pytest -q
```
